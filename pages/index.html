Variant ETL: Raw VCF files in, clean queryable variants out, checked line by line.

Every record is validated against the reference genome, rewritten into the form bcftools norm produces and bulk-loaded into PostgreSQL by parallel workers.

Malformed, misaligned, multi-allelic or out of range

Most raw files need cleaning.

The same deletion can be written several ways, and a QUAL of inf, a chromosome the reference lacks or a REF that disagrees with the genome all turn up in real files. The pipeline refuses such lines with a reason, rewrites the rest into one standard form and loads them so a region query takes milliseconds. Every number below comes from a real run of the bundled sample. How a line is checked

Every refused line keeps its reason

Every line, checked, on record.

Seven checks run in a fixed order, so each refused line gets exactly one reason. Lines that pass are split, trimmed and left-aligned, then loaded with COPY, one transaction per chunk. The board is the bundled sample's run.

1 → 4 worker containers: 1.79× on ClinVar, 1.87× on synthetic records, on one laptop that also runs PostgreSQL, Redis and MinIO. Method and raw numbers

A 10 kb region query on ClinVar takes 1.6 ms (median) with the (job_id, chrom, pos) index and 64 ms without it.

A chunk that crashes after COPY but before COMMIT leaves nothing behind, and its retry loads every row exactly once.

Docker, uv and make are all it needs

Run it.

  1. Clone

    git clone https://github.com/aleksandrahodzzik/genomic-etl-pipeline

  2. Start the stack

    make up starts PostgreSQL, Redis, MinIO, the API and a worker, and returns when they are healthy.

  3. Open the web UI

    At localhost:8000, with this same sample already loaded. Drop in your own VCF and FASTA.

  4. Scale out

    docker compose up -d --scale worker=4, then make bench to measure it.
